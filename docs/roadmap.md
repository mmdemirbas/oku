> [!TLDR]
> Most of the chart kit is interactive — tooltips, click-pin, cursor sweep, fullscreen-preserving lightbox, deconflicted labels, family-grouped catalog with clickable mini-cards. Open work concentrates on legend interactivity for the long tail and a lightbox scrollbar + minimap.
>
> - Interactivity coverage: every variant in the table below fires a contextual tooltip on hover with real per-anchor data. Cartesian + ridgeline + sparkline + gauge carry a synced cursor that updates the tooltip per-position.
> - Visual polish: quadrant + bubble label deconfliction is no-fly-zone aware. Parallel-coordinates line stroke 3.6 → 5px with fade-others on hover. Donut/pie pinned slices scale + accent-stroke. Mermaid fonts clamped to 13px, aspect-fit caps tall portrait diagrams.
> - Layout: source / render columns box-top aligned across every example-pair on reference / charts / tables — zero pixel delta.
> - Tooltip: width-stable across pin states; explicit × close button when pinned; `_tipPinned` flag stops cursor-driven charts from overwriting pinned content.
> - Pick-by-family: 43 clickable mini-cards each with a tiny live render — readers scan the shape they want and click straight into the variant's full example.
> - Robustness is the other half of the board: vendored typography, an atomic
>   build, listener teardown, a keyboard-reachable sidebar collapse. Thirteen
>   items, filterable by area and priority below.
> - `oku` is on PATH as a system command (uv tool install).

## Recent landings {#recent}

- Nested code highlighting was never a missing feature; the kit was deleting it. Prism does the work already — its markdown grammar wraps a fenced block in one `token code` spanning every line and puts `token code-block language-bash` inside it, and its markup grammar hands a `<script>` and a `<style>` body to JavaScript and CSS. Measured on the same source: raw Prism produced `code-block language-bash` with `builtin class-name`, `operator`, `function` and `parameter variable` inside it, and what reached the reader from the kit was three bare `token code` spans with no language at all. The line splitter — the pass that groups a block into one `.okt-code-line` per source line so lines can be numbered and folded — handled an element straddling a newline by cloning it per line and assigning `textContent`, which flattens every descendant. Its own comment stated the assumption and named the exception it was wrong about: "complex nested tokens across newlines are very rare". A fenced block inside a markdown sample is exactly that shape, and this repo's documentation is made of them. The splitter recurses now: a shallow clone opens, the children walk through the same emitter, and each break closes and reopens the whole open stack, so nesting survives to any depth. The HTML half looked like it worked and did not — the kit's own nested pass was re-highlighting `.token.script` by hand after the splitter had flattened Prism's `language-javascript` span, so the colours came back and the structure did not. Measured after: the HTML block carries five nested language spans (three `javascript`, two `css`) against none before, and the markdown block one `bash` with six tokens in it against zero. One defect the rewrite introduced and the test found: an element whose content ENDS on a break gets a clone reopened that nothing is emitted into, and the per-break pruning only reaches clones a LATER break arrives at — which left an empty `language-javascript` and an empty `language-css` on the page, spans the fold pass and the copy path both walk. Each element prunes its own clone as it closes.

- A network node moves with the arrow keys, and the board row that asked for dragging was describing something already shipped. Reading the source found `_wireNetworkDrag` complete; measuring it in a browser found the drag working — a node went from (316.4, 276.4) to (377.5, 235.6) and all three edges touching it followed. What the same measurement found is the gap nobody had written down: each node group carries `tabindex="0"`, so Tab reaches every node in the graph, and every key did nothing. That is the `role="button"` defect the filepath chip had, wearing a different element — focus is a promise — and it is worse here, because untangling was the whole point of the interaction and there was no other way to do it. Arrows nudge, Shift takes four steps at once, and the step is a fortieth of the viewBox's short side so one press is visible on any chart without a reader holding a key down to cross the figure. Both paths go through ONE mover: a drag and a nudge that each wrote the transform, the two data attributes and every touching edge would be two copies of one rule, and the second to change is the one that stops matching. The mover also clamps to the viewBox, which neither path did — off-canvas is worse for a nudge than for a drag, since a pointer is still holding the node it took away where thirty presses of one key leave nothing on screen to aim at. One test was written and then deleted rather than kept: the arrow key's `preventDefault` could not be shown to do anything, because on a document with 3100px of scroll available and nothing hidden on `html` or `body`, a Chromium `<g>` with `tabindex` does not scroll the page on an arrow key with the call or without it. The call stays as the correct thing to do and nothing claims it was observed doing anything.

- Thirty-five fixed sleeps in the browser suite became waits on the thing they were waiting for, and the measurement says the reason is not speed. 96 calls and 49.5 s of declared sleep down to 61 and 20.9 s; the largest single one was 6 s, paid on every run to catch a request that arrives in about 300 ms. Wall clock, measured back to back on the same machine: 592.5 s against 580.1 s, and a later run of the converted suite came in at 615.6 s with 168 s more CPU — which says the variance between runs is bigger than the effect, so there is no speed claim to make here. **What the work buys is a flake class, and it produced its own evidence.** `test_filepath.py`'s card helper waited for "a tooltip with text", which answers yes while the PREVIOUS test's card is still on screen: the module's earlier test hovers a chip and never leaves, so the helper read a stale tooltip and passed. The 350 ms sleep had been hiding that, not preventing it. Three shapes cover almost all of it. `after_rerender` stamps a diagram's `<svg>` before an action so the wait can tell a NEW render from the one already there — "is there an svg" answers yes throughout, which is why a theme flip sat behind 3.2 s and now takes 0.305 s. `measured` waits for an expression to stop changing and then returns it, so a wait and the assertion after it cannot watch different things — the shape every hover-then-read-a-computed-style test had. `settled` does the same for an observation that lives in PYTHON rather than in the page, which is what the request list a network test asserts on is; mirroring that count back into the page with an `evaluate` from inside a request handler is the other way to do it and it re-enters the driver during navigation. One sleep stays a sleep and now says why: a test proving a tooltip never appears cannot wait for an absence, because a stability poll starting at zero returns while the show delay is still running and passes without testing anything.

- The filepath chip is nudged for and rewritten to, because knowing about a primitive is not the same as reaching for it. Documents keep writing a path as a bare code span — a dead end, where the reader leaves the page, finds the file and comes back — and most often in a table, which is a list of things to go and find. `path-in-code-span` had existed for exactly this and was an `info`, which is one summary line naming the code, so it reached nobody: measured on this repo's own docs, ten spans across six pages, including the reference page that documents the chip and a glossary page naming a registry file. It is a **warning** now. The gate had already answered the objection info was chosen for — `_looks_like_a_path` requires a SEPARATOR, so a bare `kit.json` in a sentence telling the reader to create one is not judged at all, and the file must additionally resolve inside the project. What info bought was invisibility. Raising a severity without a mechanical remedy is nagging, so **`oku check --fix`** ships with it: it rewrites prose, GFM cells and `oku-*` payloads, leaves front matter, plain fences, island raw-text regions and existing links alone, re-parses every fence it touches so a payload that stopped being JSON is reverted whole rather than written out broken, and is idempotent because a chip's label is a code span inside a link construct. It is defined as APPLYING WHAT THE REPORT SAID — it takes the issue list rather than walking the tree again, since which pages qualify has several answers already baked into the check and a second walk is a second set of answers waiting to diverge. A materialised page is exempt from both: a README renders through the kit and is also read on GitHub, where `#f/…` is a link to an anchor that does not exist. One bug found while building it, and it is the same one the island lint already carries a comment about: counting `<pre>` on the unmasked line makes the sentence “multi-line code in an island is a `<pre>`” open a raw-text region that never closes, which silenced 8 of the 10 rewrites on this repo's own docs. The chip was measured working in both table spellings first, since the whole push rests on it: one visible chip per cell, the preview carrying the file's text, rows within 4px of a plain-text row, and no sideways scroll at 360px.

- The theme control has three stops again, and System is the only auto there is. It had two, Light and Dark, with following the OS surviving as a policy: you re-entered it by picking whichever theme the OS was already showing, a 4px dot said you were in it, and an explicit choice expired at the next OS flip — `theme-pref` stored `"<chosen>@<os-at-choice>"` so a flip that happened with the tab closed expired it too. All three existed to fit the rule into one corner button that could show one of two icons. The reason a third stop was cut in the first place is real and it is not the count: on a cycler, `system` and `dark` under a dark OS are the same pixels, so the only way to know which one you were in was to read the icon. Drawing the stops fixes that — a segmented control shows all three with the chosen one pressed, so they are two visibly different states even when the page is the same colour. Both mechanisms cost the reader something the panel does not have to charge: the expiry meant "always dark" could not be pinned past an OS flip, so a reader whose OS runs on a schedule re-picked it once a day, and the hand-back gesture meant the way to auto was knowing that clicking a theme you were already in did something other than nothing. A choice now holds until the reader changes it, `theme-pref` stores the bare mode, and the dot is gone with the policy it marked. Pressed is keyed off `data-theme-mode` and not `data-theme` — on System with a dark OS those are `system` and `dark`, so the other one lights Dark while the reader is on System and looks correct in every light-OS test. The absence of a key IS System, so a reader who has never touched the control and one who chose System back cannot drift apart, and a stored value naming no theme falls back there rather than pinning someone to a theme they cannot get out of; a `"dark@light"` from the old kit is read for its first field and rewritten bare, because under this rule that is simply still their pin. The `matchMedia` listener returns early unless the mode is System, which is the whole difference between the three stops and the two they replaced. Measured at 320px: the three-segment control is 214px inside a 266px row and the panel's right edge stays 16px inside the viewport at 320, 360 and 1280.

- The reader can make the document bigger, and the document is all of it. A text-size ladder from 80% to 200% steps `zoom` on the reading column, which is the one mechanism that takes text, inline SVG, Mermaid's output and images together and still REFLOWS — a paragraph at 1.5 wraps at 1.5. Measured on this repo's own charts page at 1440px: the same string renders 145px wide at 1.0 and 218px at 1.5, a chart's rendered height goes 55px to 97px, a sidebar tree row 28px to 42px, and the 44px chrome buttons, the rail and the sidebar's own 320px width do not move at all. Three things it broke and one it exposed. `--content-width: 100vw` for the `max` mode asked for 125% of the viewport at 1.25x, because a viewport unit resolves against a containing block zoom does not touch; it is `100%` now. A `position: fixed` tooltip inside the zoomed column takes the zoom with it — the coordinate written into `left` is multiplied, and the coordinate came out of `getBoundingClientRect()`, which does not multiply — so a chart tooltip landed 189px from its bar at 1.25x and 360px at 1.5x, and the three tooltips that live inside `main` now write through `__okuSetFixedPos`. `main`'s padding is divided by the scale, because on a phone the column is already clamped to the viewport and every pixel the padding gained came off the figure: a chart went 286px to 256px when the reader asked for MORE. And the exposed one is older than the feature: `minmax(200px, 1fr)` is a floor a track refuses to go below, so at 2x on a 360px viewport eight compare cards laid out 400px wide inside 360px — every auto-fill floor is `minmax(min(Npx, 100%), 1fr)` now, and a sparkline row that sized to max-content with no `max-width: 100%` went with it.

- Every presentation choice is behind one button. The flex row fixed the corner's arithmetic and not its count: six buttons wanted that corner — personalize, search, language, warning, theme, width — and text size was the seventh. Six 44px boxes over the top of the reading column is a toolbar the reader reads before every click, and five sixths of it is set once. The split is by frequency, so search stays out (used while reading) and so does the warning indicator (an alarm, which must never hide itself); text size, width, theme, language and placeholders are rows in the menu. It pays twice: an icon-only cycler exists because a 44px box has no room for words, so the width control's three-segment icon had to be hovered to be read and announced its stops in a `title` nobody opens. A row has room for one labelled button per stop, so the state is visible instead of announced. Rows register rather than being listed, for the reason the flex row exists — language appears only where there is a translation, placeholders only where a snippet declared some — and the panel does not close when a control inside it is used, because finding the right text size is three clicks and a menu that closed on the first would make it nine.

- The prose rules reach the prose now, not only the paragraphs. `placeholder-text` read paragraphs and nothing else, while `process-breadcrumb` — three lines away in the same function — already walked prose nested inside typed payloads. Measured on one page carrying the same `TODO` in a paragraph and in a step body: one warning, from the paragraph. This repo's own [`examples/iceberg.md`](#f/examples/iceberg.md) carried `Mermaid diagrams (still TODO in build sequence step 11)` in a compare-grid card, past `oku check --strict`, long enough for all three things that card listed as future work to have shipped; the card is rewritten to what the kit does today, and the stale copy is what the gap was hiding. Both rules also stopped at an HTML island — they sat at the foot of the prose loop past three `continue`s, so nothing between a `<div>`'s tags was ever read, and an island is markup the reader sees through. The exception is raw text, tracked here rather than left to the island walk because that walk arms only on an island's opening tag: a `<pre>` inside a `<div>`, which is the idiom the kit documents for multi-line code in an island, was an ordinary island line to it, and `// TODO: implement` in a sample is the sample. Closing the first gap surfaced the other half — [`docs/cli.md`](#f/docs/cli.md) failed its own check, because the severity table has to spell the four placeholders it catches and that table is a payload. A token in a code span is the token being named, so code spans are masked before the placeholder search; masked to spaces rather than stripped, since every locator in the checker is a line number into the source as written and deleting a span moves everything after it.

- A page whose subject IS a history can now cite it. `process-breadcrumb` scoped itself by who WROTE the prose — pages materialised from repo markdown are exempt because the kit does not own that text — and a hand-authored measurement report correcting an earlier round is owned by its author and is still not kit documentation. It had no escape: every sentence naming the round it corrects raised a warning, `oku check --strict` exited 1, and the only way past the gate was to rewrite each citation into a date, which loses the reference the reader needs. Observed at 29 warnings on one document, all on correct prose. `documents_history: true` in front-matter exempts that one rule on that one page. It is not folded into `skip_prose`, the seam that looks like the fix: that turns off every prose rule, and a stray placeholder left in a report is still one — measured, `placeholder-text` still fires under the exemption. It is not a kit.json switch either, for the reason `skip_gitignored` states about itself: a tree-wide setting exempts pages written later, from a file nobody opens while writing prose. Both emitters honour it, because the same sentence in a step body raised the same code from a different call site. The warning names the way out, since a warning on correct prose with no named escape is one the author works around by deleting the citation.

- Four of the seven accent tokens the front-matter spec documents were never a colour. `_applyAccent`'s palette map held three; `violet` and `green` fell through to a fallback that set `--accent` from the browser's own name table and left `--accent-soft` and `--accent-strong` on indigo, so a callout drew one hue on its rule and another on the surface behind it. `rose` and `slate` are not CSS named colours, so the declaration was invalid, `--accent` computed to the literal string, and `buildConfig` handed that string to Mermaid — which requires a concrete colour. Measured on the reproduction: `accent: teal` drew a 155px figure, `accent: rose` drew 0px and an "Unsupported color format" card for every diagram on the page, and `oku check --strict` called both pages clean. All seven carry a light and a dark family now, each clearing 4.5:1 on the page background and on its own plate in both themes (lowest measured: amber's strong-on-soft at 4.51, green's accent-on-bg at 4.80). A value outside the map is handed to the browser first, so `rebeccapurple` and `hsl(280 60% 40%)` get a matched soft, strong and dark variant instead of a lone hue; one the browser cannot parse keeps the default accent and says so, because a wrong colour is recoverable and a page of error cards is not. `oku check` says `accent-unknown` for a bare word that is neither, and `diagram-unknown-token` for a mermaid `classDef` naming a `var(--token)` the kit being checked does not define — the shape of the report that arrived from another project, where the skill briefing documents `var(--series-N-soft)` and the installed tool read `kit 2026-08-20-r50`, three weeks behind the kit that ships them.
- A curly quote in a diagram label is a character, not a delimiter. The diagram element decodes its source before Mermaid parses it, because a fence's body arrives through the markdown pipeline escaped — `&lt;` for `<`, and `--&gt;` for an arrow, which is why the pass exists. Two more rewrites sat beside those on the reading that a smart quote is another escaping artefact, and turned `A["the “quoted” label"]` into `A["the "quoted" label"]`, whose straight quotes close the string one word in. Measured on a page whose author had done nothing but write typographic prose inside a node: six labels, no figure, `Parse error on line 2`, and a clean `oku check --strict`. ## Locked decisions {#decisions}

Each was an open question once; collected here so future contributors don't relitigate.

- Project name = oku (Turkish 'read!'). Every layer reads `oku`: package (src/oku/), kit CSS prefixes (okt- / okc- / okd-), JS globals (__oku*), event names (oku:*), data-attrs (data-oku-*), and custom-element tag names.
- GitHub remote URL stays at github.com/mmdemirbas/html-doc — the schema $id, the git-clone example, and the jsdelivr CDN URL all point there. The local repo directory name follows the remote.
- Code / output columns inside example-pair MUST align at the top edge of the box. No 24px spacer for non-code outputs — the visible top edges of the code and output columns line up regardless of the output kind.
- Tooltip width is stable across pin states. Pinned vs unpinned switches the footer text + close-button visibility, NEVER the bounding box.
- ext-ref host is NOT a navigation link. Clicking pins the tooltip; the destination URL lives as a clickable domain anchor inside the citation card. One affordance per element.
- Pagefind is a Python dep, not a system binary — `oku[search]` extra pulls `pagefind[bin]>=1.5`.
- Layout = option A (centered document, three-mode content-width cycle: narrow / comfortable / max).
- Tier 3 viz (sankey / network / scatter-matrix / parallel-coordinates / chord / geo) all ship as kit-native chart types — no third-party chart library.
- Charts / tables / diagrams are sub-pages of Reference (meta.parent: 'reference').
- Source format = v3 markdown-first. A page is `.md`: YAML front-matter + a strict-GFM body (no indented code blocks, no setext headings, no lazy continuation — linted, still valid GFM); kit primitives are ```oku-<kind> fences with one compact JSON body; diagrams are ```mermaid fences with an italic caption line; raw block-level HTML islands (script included) pass through to the kit untouched and are audited by `oku check`. Decided after measuring tokens (markdown ≈ 20% leaner than v2 JSON, far leaner than HTML), LLM emission accuracy, and ecosystem direction; HTML-first was evaluated and rejected for repo-resident continually-edited sources. JSON pages (v1/v2) keep rendering via shims; `oku migrate` converts them.
- Build outputs = two trees (standalone, site). No dist/markdown twins — the .md sources are the canonical AI/LLM surface; llms.txt lives at the site docs root.

## Principles {#principles}

Reader-, author-, and maintainer-facing rules every change honours.

- Single LEFT sidebar — TOC + site tree stacked. No right TOC, no mid-edge tab.
- Visual-first authoring. Pros/cons → comparison-cards, metrics → kpi-grid, trade-offs → table-with-chips. Paragraph + bullets is the fallback, not the default.
- Every fix pairs with a Playwright check. Browser-level fixes ship with numeric assertions captured in the commit body.
- Numbers in counters / badges only — no English words baked into the kit.
- No demo sibling pages. Every example for a primitive lives next to its heading.
- No process / round / historical references in docs — describe current behaviour, not how it got there.
- Layout invariants are numeric, not eyeball — express the rule as a boundingBox / computed-style assertion or accept it isn't a rule yet.
