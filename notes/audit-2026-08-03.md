> [!TLDR]
> A reader reported one thing: **a link inside bold rendered as literal text**. That defect turned out to be the visible edge of a parser that had never been tested construct by construct.
>
> - 36 defects fixed across the markdown parser, the CLI, the runtime chrome and the accessibility layer.
> - Two documented features did not exist at all: footnotes and reference-style links.
> - Six of this repo's 32 pages served a completely empty `<main>` under `oku serve`.
> - Test count 366 → 410; console errors across the doc tree 24 → 0.

## Markdown parser {#parser}

The reported defect: emphasis, link and code bodies were emitted as plain **text**, so nothing composed. `**[a](b)**` rendered as the characters `[a](b)` in bold, and the author worked around it by moving links out of the bold run.

Bodies parse recursively now. Only a code span keeps a literal body — that is the rule that protects it. Fixing that opened the question of what else the parser got wrong, and the probe answered it.

### Two documented features that did not exist {#missing}

The reference's conversion table has always listed **footnotes** and **reference-style links**. Neither was implemented; an author following the reference shipped raw syntax to readers.

Both resolve **page-wide**, which is the part that needed care: `md_to_v2_page` opens a new `b[]` string at every typed fence, so a definition routinely lands in a different string than its reference. The renderer collects and strips definitions from every string before it emits anything.

An undefined reference stays literal text, as GFM specifies — invisible in a diff and easy to miss on a long page — so `oku check` now warns on one.

`oku check` had the mirror of the parser's registry defect: it scanned for references with `[\w-]+`, so a multi-word reference was never collected and an unresolved one passed the gate in silence.

## Runtime chrome {#runtime}

Two defects, both invisible until a page had more than one of something.

- **Site-tree crash.** The tree builder indexed the root level's page bucket without checking it exists. With every page under `docs/`, that bucket is undefined, the render threw, the throw was swallowed by the manifest loader's `catch`, and the sidebar told the reader to run `oku serve` — on a site whose manifest had loaded fine.
- **Shared clip-path id.** Every chart emitted `<clipPath id="okc-clip">`. SVG `url(#id)` resolves against the whole document, so all five charts on the charts page clipped to the *first* chart's plot rectangle.

> [!NOTE] Considered and left alone
> Component labels — callout titles, card titles, chart titles — render
> as `h4`. That skips a level after an `h2` section, but they are labels
> of a card, not entries in the document outline, and the TOC only
> collects `h2` and `h3`. Changing the tag would touch twelve CSS
> selectors for a benefit an author never sees. What an author does
> control is now linted: a heading that skips a level in the source is
> flagged.

## Still open {#open}

> [!NOTE] Mermaid's own duplicate ids
> Diagram pages carry repeated `arrowhead` and `node-undefined` ids. That markup comes from the library, not the kit, and the markers it collides on are identical, so the render is unaffected. Worth revisiting if diagram theming ever diverges per instance.

> [!NOTE] Alternative-format emitters
> The `.adoc` / `.dj` / `.src.html` converters carry a documented subset. They gained the nesting fix, but not images, strikethrough, footnotes or reference links. The comparison corpus does not exercise those, so nothing is currently wrong — it is a gap to close if a format is promoted out of comparison.

> [!NOTE] Designer polish
> Token temperature, TL;DR weight and vertical rhythm remain by-eye judgements from the design pass and are unchanged here.
