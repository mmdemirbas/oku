# Bug hunt: the IntelliJ plugin and `oku preview --serve`, 2026-10-18

Scope: every Kotlin source under `src/main/kotlin`, `install.py`, and the
oku side the plugin talks to: `_preview_serve` and the request handlers in
`src/oku/cli.py` (`preview_page`, `check_buffer`, `fix_buffer`,
`registry_entries`, `heading_lines`, the greeting). Branch
`fix/plugin-bug-hunt`, from `dee0d7c`.

Baseline: plugin suite 48 tests green. Python: 3414 passed, 10 failed and
19 errors in a run that shared the machine with a Gradle build; the 11
failing files rerun alone gave 154 passed and 1 failed, the one below
under "Recorded, not fixed".

Each is a `test(...)` commit that fails, then a `fix(...)` commit.

render requests on a tree with `skip_gitignored` printed protocol lines

The IV.5 fix in `OkuChipFix` is not exercised by a test: the headless
progress gives a test no handle on the indicator to cancel.

## Recorded, not fixed

- **XII.1, wall clock for an interval.** `OkuRegistryCache` measures
  freshness with `System.currentTimeMillis()`. A wall clock stepped
  backwards makes every entry's age negative, so a stale answer is served
  and never pruned until the clock catches up. Rare trigger. The fix is
  `System.nanoTime()`; a failing test needs a clock seam the code does
  not have.
- **Kit test, outside this scope.**
  `browser/test_prism_asks_only_for_what_it_has.py::test_the_vendored_components_are_all_present`
  fails on a freshly vendored tree: `prism_components_needed` skips
  `css`, `javascript` and `markup` because `prism.min.js` bundles them,
  and the test requires a file for every name in `_PRISM_LANGS`. It passes
  in a checkout whose vendor cache predates the catalog. The test, not the
  vendoring, looks wrong.
